# AGENTS.md — правила проекта ORION для Codex

Хакатонный проект: AI-агент с веб-интерфейсом в стиле HUD / JARVIS. Главная цель — один основной сценарий, отполированный до уровня готового продукта. Красота, понятность и «агент виден в работе» важнее количества фич.

Читай этот файл целиком перед каждой задачей. Если задача противоречит правилам — сначала спроси. Объясняй мне всё простыми словами: я дизайнер, а не разработчик.

## Визуальный стиль: HUD / JARVIS

- **Фон:** графит `#0a0b0d` + шейдер «Атмосфера». Только тёмная тема.
- **Палитра:** текст `#ece8e1`, вторичный `#8e9097`, третичный `#585b62`. Акцент — сигнальный оранжевый `#ff7a2f`. Небесный `#8ec9ff` — данные и «норма». Статусы: критично `#ff4a3d`, внимание `#ffc24b`, норма `#8ec9ff`.
- **Правило цвета:** оранжевый = «агент действует / нужно действие», небесный = «данные / всё хорошо», серый = структура. Не красить оранжевым всё подряд. Не больше одной primary-кнопки на экран.
- **Только токены:** `bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`, `border-border`, `text-sky`, `text-warning`, `text-destructive`, `bg-panel`, `border-line-strong`, `text-dim`. Никаких hex в компонентах.
- **Формы:** скругления 0 везде (кроме точек-индикаторов). Панели — полупрозрачные со скобками в углах (`hud-panel` или Card). Над панелью — плашка-заголовок `hud-label`.
- **Типографика:** КАПС с трекингом для лейблов, табов, статусов, заголовков (`hud-caps`). Все цифры, ID, логи, таймкоды — моно (`hud-num` / `font-mono`). Шкала: 11 / 12 / 14 / 16 / 20 / 24 / 32 / 48.
- **Отступы:** шкала Tailwind с шагом 4px. Внутри панели плотнее, чем между панелями.
- **Запрещено:** светлые карточки, мягкие тени, скругления, градиентные заливки как декор, эмодзи, выделение одного слова заголовка другим цветом, больше одного WebGL-объекта на экране (фон не считается).

## Тема ORION HUD v2: что работает само

Штатные компоненты уже стилизованы и анимированы через `data-slot` / `data-variant` / `data-state`. Не добавляй им свои радиусы, тени и анимации.
- **Card** — стекло, скобки, boot-появление из блюра. Каскад: `style={stagger(i)}`. Без анимации: `data-static`.
- **Button** — капс; primary со свечением и бликом; outline со скобками. `data-tone="sky"` — небесная, `data-loading` — полосы «выполняется».
- **Badge** — контурные HUD-теги. Тон: `data-tone="sky" | "warning" | "danger"`.
- **Dialog / AlertDialog** — раскрытие от центральной линии. **Dropdown / Select / Popover** — шторка. **Tooltip** — шторка слева.
- **Tabs** — подчёркивание вырастает, контент открывается шторкой. **Table** — строки въезжают каскадом.
- **Progress** — свечение и блик. **Skeleton** — блик. **Checkbox** — pop. **Toaster** — HUD-тосты (`toast.success`, `toast.error`, `toast`).

**Состояния агента** — `data-agent` на любом контейнере:
- `working` — луч бежит по верхней грани, оранжевая рамка
- `waiting` — пульсирует оранжевым (нужно решение человека)
- `done` — вспышка небесным
- `error` — красная рамка и встряска

Для потомков: варианты `agent-working:`, `agent-waiting:`, `agent-done:`, `agent-error:`.

**Утилиты:** `hud-panel`, `hud-frame`, `hud-label`, `hud-tag`, `hud-cut`, `hud-octagon`, `hud-caps`, `hud-num`, `text-glow`, `hud-grid`, `hud-blueprint`, `hud-dot`, `hud-beam` (+ `data-active`), `hud-sheen`, `hud-scanner`, `hud-scanlines`, `hud-noise`, `hud-boot`, `hud-reveal`, `hud-stagger`, `hud-glitch` (+ `data-text`), `hud-caret`, `hud-flash-up/down`, `hud-draw` (`--hud-len`), `hud-ticks` (`--value`), `hud-divider`. Тени: `shadow-glow`, `shadow-glow-strong`, `shadow-glow-sky`, `shadow-glow-danger`.

## Моушн

- Тайминги только из токенов: CSS `--dur-fast/base/slow/boot`, `--ease-hud`; в Motion — `lib/motion.ts`.
- Анимируй `transform`, `opacity`, `filter`, `clip-path`. Не анимируй width/height/top/left — для раскладки используй `layout` из Motion.
- Один сигнатурный момент на экран (переход «старт → агент работает»). Бесконечные анимации — медленные и тихие. Быстро двигается только то, что показывает работу агента.
- `prefers-reduced-motion` уже учтён темой — не ломай это.

**Обязательный набор HUD-анимаций в сценарии:**
- Загрузка экрана: карточки каскадом (`stagger`), заголовки через `DecodeText`, цифры через `CountUp`.
- Агент работает: `data-agent="working"`, `hud-beam` на командной строке, шаги появляются по очереди, журнал печатается через `TypeLine`.
- Находка: выноска / подсветка + статус-тег; при критичном — `hud-glitch` один раз.
- Нужно решение: `data-agent="waiting"` на карточке подтверждения.
- Результат: метрики накручиваются, `data-agent="done"`, тост.

**Libraries.dev — как использовать в этом стиле:**
- состояние агента → `<ThinkingOrb state="searching" size={64} color="#ff7a2f" />` (20 — в строке шага)
- командная строка → `<BorderBeam size="md" colorVariant="sunset" staticColors borderRadius={0} active={running}>`
- карточка подтверждения → `<BorderBeam size="pulse-outside" colorVariant="sunset" staticColors borderRadius={0}>`
- голос → `<VoiceBeam colorVariant="sunset" borderRadius={0}>`
- несколько агентов → `<BotAvatar>` цветами палитры; генерация изображения → `img-fx`
- `liquid-gooey` и `metal-fx` не использовать (ломают HUD). Меню действий — радиальное (паттерн 35), главная кнопка — «заряд» (паттерн 36).

## Паттерны агентского интерфейса

1. **Старт:** крупная командная строка + 3 чипа-примера (клик сразу запускает сценарий).
2. **Агент работает:** статус и план из 3–5 шагов, у шага статус ожидание → выполняется → готово / ошибка. Вызовы инструментов — компактно, раскрываются по клику. Журнал справа.
3. **Результат:** итог первым и крупно, потом метрики, потом детали и источники.
4. **Действие:** карточка подтверждения — что именно сделает агент, кнопки «Подтвердить» и «Изменить».

У каждого экрана 4 состояния: пустое, загрузка (скелетоны или шаги, не голый спиннер), ошибка (что случилось и что сделать + «Повторить»), успех.

## Бэкенд агента (для напарника)

- `app/api/agent/route.ts` — POST, принимает запрос пользователя, возвращает результат в формате из `lib/types.ts` (контракт фронта и бэка).
- Шаги агента по возможности стримить (Server-Sent Events или ReadableStream): событие на каждый шаг — `{type:"step", id, title, status}`, находки — `{type:"finding", ...}`, финал — `{type:"result", ...}`. Тогда интерфейс показывает работу агента живьём.
- Если стрим не успеваем — отдаём один JSON со списком шагов, а интерфейс проигрывает шаги по таймеру.
- Ошибки: понятный JSON `{error, message}` и код ответа; интерфейс в этом случае показывает моки (демо-режим).

## Тексты в интерфейсе

- Язык интерфейса: русский (если задача требует — казахский или английский).
- Кнопка говорит, что произойдёт: «Сформировать отчёт», а не «Отправить». Одно действие называется одинаково везде.
- Ошибки: что пошло не так и как исправить, без извинений.

## Демо-режим

- Все данные для сценария — в `lib/mock/`. Главный экран работает и без бэкенда.
- С реальным API: если запрос упал или идёт дольше 20 секунд — показываем моковый результат (флаг `NEXT_PUBLIC_DEMO_FALLBACK=true`). Демо не должно сломаться на сцене.
