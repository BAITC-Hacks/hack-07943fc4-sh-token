# Бесплатное демо STRATA на Render

Статус: конфигурация подготовлена; публичный адрес добавляется только после
успешного деплоя и проверки. Ноутбук команды для работы сайта не нужен.

Текущий блокер: репозиторий приватный, доступ Render к нему не предоставлен
по решению владельца. GitHub-интеграция не подключалась, сервис не создан.
Альтернатива — собрать Docker-образ и разместить его в согласованном реестре,
затем подключить Render как Existing Image. Это отдельное решение: образ содержит
исполняемый код и обезличенные данные, его нельзя публиковать без разрешения.
На текущей машине Docker отсутствует, контейнерная сборка пока не проверена.

## Что разворачивается

Один Docker-контейнер: Next.js standalone + Python 3.11 + окружение uv.
Сырые parquet организаторов входят в образ. HTTP-запрос запускает настоящий
пайплайн, результаты живут в памяти одного процесса. База данных и диск не нужны.

Только **Web Service / Free**, не Static Site. В `render.yaml` явно задан
`plan: free`. Платные сервисы и постоянные диски не создаются.

## Размещение

1. Войдите в [Render](https://dashboard.render.com/) через GitHub. Дайте доступ
   только к репозиторию команды `BAITC-Hacks/hack-07943fc4-sh-token`, если позволяет
   настройка GitHub App. Доступ к организации может требовать одобрения владельца.
2. Откройте **New → Blueprint**, выберите репозиторий и ветку с этой конфигурацией.
   После merge используйте `main`. Render прочитает `render.yaml` и Dockerfile.
3. Убедитесь, что создаётся единственный сервис `strata-demo` с тарифом **Free**.
   Не подтверждайте переход на платный тариф. Если аккаунт требует карту или
   платный план, остановитесь и выберите другой вариант, не вводите платёжные данные.
4. В приватных переменных сервиса укажите `OPENAI_API_KEY` и `OPENAI_MODEL`.
   Используйте значение модели, уже проверенное в локальном `.env.local`.
   Не копируйте ключ в чат, README или GitHub. Не используйте префикс `NEXT_PUBLIC_`.
5. `DEMO_AUTH_USER` равен `jury`. `DEMO_AUTH_PASSWORD` Render генерирует сам.
   Сохраните его из приватной панели сервиса и передайте жюри отдельным каналом.
   Если сервис создаётся вручную, задайте случайный пароль минимум из 16 символов
   и `STRATA_PUBLIC_DEMO=true`. Не используйте пароль своего аккаунта.
6. Запустите deploy и дождитесь успешных сборки и healthcheck `/api/health`.
   Docker запускает сервер на `0.0.0.0:$PORT`; отдельная Start Command не нужна.
   Проверка здоровья не вызывает OpenAI и не раскрывает секреты.
7. Откройте выданный Render HTTPS-адрес в приватном окне. Без авторизации страница,
   граф и API должны запрашивать пароль. После входа выполните сценарий ниже.
8. Сохраните подтверждённую ссылку в README и форме сдачи. Логин/пароль передайте
   в закрытых инструкциях жюри. Не добавляйте пароль в URL или публичный репозиторий.

Автодеплой отключён (`autoDeployTrigger: off`), чтобы случайный push не перезапустил
демонстрацию. После нужного merge запускайте ручной deploy последнего коммита.

## Проверка после деплоя

1. Без пароля `/api/assistant`, `/api/analysis` и `/data/graph.json` недоступны.
   `/api/health` возвращает только `{"status":"ok"}`.
2. После входа нажмите «Начать исследование» на комплекте организаторов.
3. Убедитесь: 2 248 узлов, 81 seed, 91 кластер и топ из 50 записей.
4. Скачайте три CSV из «Файлов расчёта», добавьте одного клиента в список проверки.
5. Откройте клиента `100000004299488100` и спросите AI:
   «Составь справку по выбранному клиенту». Проверьте вход 1 749 000 KZT,
   выход 344 999 KZT и ссылку на тот же GID.
6. Спросите «Какой остаток на счёте клиента?» — система должна сообщить, что
   запрос не поддерживается, а не выдумать остаток.
7. Повторите проверку с другого устройства. Проверьте холодный старт после простоя.

Успешная локальная сборка не заменяет эту облачную проверку. На Free ограничены
RAM/CPU; пригодность текущего образа нужно подтвердить фактическим запуском на сервисе.

## Где ключ и кто оплачивает AI

`.env.local` — способ задать переменные при локальном запуске. На Render те же
переменные внедряет окружение хостинга. Код читает `process.env.OPENAI_API_KEY`
только на сервере, жюри не получает ключ и не вводит свой для работы на сайте.

Бесплатный хостинг **не делает OpenAI API бесплатным**. Запросы используют квоту
или кредиты проекта команды. Без квоты AI покажет явную ошибку, а граф/CSV продолжат
работать. Настройте ограничения и уведомления в API-проекте, следите за расходами.
Приложение ограничивает обращения: 30 в скользящий час, 200 за последние сутки,
один одновременно. Счётчик общий и хранится в памяти, перезапуск его сбрасывает.
Это защита от случайного перерасхода, не гарантированный лимит в деньгах.

В образ и Git не попадает `.env.local`: он исключён через `.dockerignore` и
`.gitignore`. Dockerfile не объявляет ARG/ENV со значениями ключей. Ключи передаются
при запуске, а не встраиваются в JS-бандл. Не снимайте скриншоты панели с раскрытыми
секретами и не прикладывайте её к сдаче.

Общая Basic-аутентификация подходит только для ограниченного демо через HTTPS.
Она не обеспечивает отдельные аккаунты, аудит действий и изоляцию пользователей.
Для банковской эксплуатации нужны собственные авторизация, хранилище и очередь.
В облачном демо используйте только обезличенные данные организаторов.

## Ограничения Free

По [документации Render](https://render.com/docs/free), после 15 минут без входящего
трафика сервис засыпает, пробуждение занимает около минуты. После перезапуска
исчезают результаты в памяти: просто выполните анализ заново. Исходный комплект
в образе сохраняется. Не используйте внешние пинги для обхода засыпания.

Бесплатные часы, трафик и время сборки ограничены. При отсутствии платёжного
метода исчерпание лимитов может приостановить сервис/сборки; при подключённой карте
возможна оплата превышений. Для строго бесплатного варианта не подключайте карту.
Заранее откройте демо перед защитой и сохраните локальный запуск как резерв.

Официальные инструкции: [Docker](https://render.com/docs/docker),
[Web Services](https://render.com/docs/web-services),
[Blueprint](https://render.com/docs/blueprint-spec),
